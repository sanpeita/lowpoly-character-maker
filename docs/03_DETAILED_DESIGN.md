# Lowpoly Character Maker — 詳細設計（うのっち承認済み・技術選定は実装前ゲート）

初版はPCブラウザ単一画面、スマートフォン対象外。将来のリグ／アニメーション対応をP0の完成条件に含めない。

参照: [概要](01_OVERVIEW.md)、[要件](02_REQUIREMENTS.md)。実装可能性の検証前なので、ライブラリ・数値予算配分・パーツ形状は**仮設計**であり確定仕様ではない。

## 境界と責務

- **UI/State**: パーツ選択、部位固定、シード、プレビュー操作、予算表示、エラー、ダウンロード操作を管理する。外部へ自動送信しない。
- **Generator**: シードと選択・ロック状態を受け取り、候補から決定的に組み立てる。ランダム抽選により固定中の部位を上書きしない。
- **Parts/Palette**: オリジナルの形状データと8色以下のパレット候補を定義する。入手元不明の外部アセットを同梱しない。
- **Validator**: 組立後および出力直前に三角化した全メッシュと相異なる出力色を計測し、超過をブロックする。UI表示値もここから取得する。
- **Exporter**: Validatorが合格したスナップショットのみGLBへ変換し、再検査可能な出力を作る。失敗時はファイルを渡さない。

データの流れ: `UI選択／シード -> Generator -> シーン表現 -> Validator -> UIプレビュー／予算表示 -> Exporter -> GLB`。プレビューと出力が別の見た目にならないよう、同一のシーン表現を共有する。

## データ契約案

- `CharacterRecipe`: `schemaVersion`, `seed`, `selectedParts`, `lockedParts`, `paletteSelection`。部位IDと色IDは定義済みのIDだけ許可する。初版ではローカル永続保存を要件にしない。
- `PartDefinition`: `id`, `slot`, `mesh`, `materialColorIds`。素体・選択パーツ・小物は出力対象ならすべて検証対象。
- `ValidationResult`: `triangleCount`, `colorCount`, `errors[]`、`valid`。GLBエクスポートにも同一の合否を用いる。
- `ExportArtifact`: GLBバイト列と検証時のRecipe／統計の対応。バイト生成後にメッシュ内容を再検査するテストを置く。

## 制約を守る仕組み

- パーツの四角面や多角形は、最終出力で三角化した枚数を数える。複数メッシュ・小物・裏面用の重複面を省略しない。
- 色は出力マテリアルの不透明なベースRGBの相異数。プレビュー照明で見える陰影はカウント対象外。8色制限を守るため任意RGBピッカーはP0に置かない。
- 素体と選択パーツの予算をテストで計測し、全ての提供候補を安全側に設計する。組合せで超過するならUIで選択不能とするか、出力前に明示的に組合せを差し戻す。黙って小物を削除しない。
- 再抽選はシード付き疑似乱数で、入力Recipeの非固定部位だけを更新。全固定なら見た目は不変で理由をUIに示す。無効なシードや未知の部位IDは安全に初期状態へ戻し、外部読み込みはP0に入れない。

## UI状態

`ready`（見本表示）／`generating`（組立中）／`invalid`（制約違反・組合せ不能）／`exporting`／`export-error`。3D描画非対応では説明と再試行を表示し、壊れた空画面にしない。選択要素には名前とキーボード操作を与える。

## 実装の小分け（Issue化の種。未登録）

1. 最小パーツ／パレット定義と、決定的なRecipe→メッシュ生成。
2. 制約計測・組合せテストと、全候補の上限検証。
3. UIプレビュー、選択、固定／再抽選、計測表示と代替表示。
4. GLB出力、独立ローダーでの再読込検証。
5. E2E操作検証、README、公開権利・パフォーマンス確認。

各Issueは依存関係、対象パス、対象外、受け入れ条件、テスト、失敗時の戻し方を付けてSolが作成済み。設計の穴をIssueで勝手に埋めない。Issue本文は文書の公開前から単独で読めるよう自己完結させた。

## Build/Test/運用・rollback

ライブラリとビルド手段は実装パッケージで採用理由・バージョン・ライセンスを確定し、READMEに**実際に動作確認した正確なコマンド**を記載する。テストにはSeed再現性、固定部位不変、全候補の制約、GLB再読込、手動UIフローを含める。依存の再現性を固定する。公開は人間の許可後とし、問題が出たら最後に検証済みの版へ戻せるようにする。コード・素材・ログに秘密情報を入れない。
